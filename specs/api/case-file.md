# Initial accepted case file

`case-file.schema.json` (`https://schemas.formspec.io/wos-api/case-file/v1`) owns the WOS service evidence and reviewer read metadata. Formspec owns the native documents. The schema exports `AcceptedIntakeEvidence`, `CaseFileRead`, `IntakeHandoffReceipt`, `AcceptedAuthoredArtifact`, `AcceptedSignatureVerification`, and `AcceptedAttachmentDescriptor`.

`POST /api/v1/intake-handoffs` accepts the unchanged canonical Formspec IntakeHandoff1.0 from an authenticated, scope-bound integration principal. `Idempotency-Key` equals the original `handoffId`. The configured exact Definition binding selects the workflow; the caller supplies no workflow selector. Resolve and qualify source evidence before invoking maintained runtime acceptance. Return `accepted` only after a real case, process, and reviewer task commit. Replay returns those same identities. `pending` means retriable source qualification or delivery before runtime acceptance; it must not finalize a deferred runtime receipt. Altered content or binding under an existing scoped key refuses.

The accepted receipt's nonempty `tasks` array is immutable initial creation metadata, using the existing `TaskListItem` shape. It is not a current task list, task-body read or notification. A deployment MUST explicitly authorize the actual producer to receive this creation receipt through its configured intake-acceptance policy: current authenticated principal and canonical actor, full deployment grants and exact scope, configured producer/source/Definition/workflow binding, and the exact accepted handoff-to-case/process association. An OAuth scope, role label, task identifier, caller filter or common storage scope alone grants no such disclosure. Current producer admission and output eligibility also apply before cached receipt disclosure and across asynchronous work. This policy does not grant current task-read or task-action authority.

The producer policy MUST cover every mandatory `TaskListItem` field (`id`, `processId`, `kind`, `status`, `title`, `createdAt`) as metadata of the actual initial creation. Include optional fields only when that policy explicitly permits them and their values are established by the same committed creation facts. In this receipt, status, title, assignment and timestamps describe the initial creation snapshot, never a later current-task query. No draft, response, task presentation context, private body or subsequent task/case state is covered. If policy or authoritative facts do not establish the required metadata, refuse disclosure using the existing problem response; do not invent values, filter `tasks` to empty, substitute a reviewer identity or describe a completed runtime acceptance as a pre-acceptance `pending` outcome solely because receipt disclosure or initial-metadata capture failed. A partially applied intake command remains governed by its existing durable retry semantics; process creation alone does not establish completed runtime acceptance.

Construct the initial metadata from exact committed process/task creation outputs or equally authoritative retained creation facts for this one accepted case/process, with the actual created task identities and configured reviewer-task association checked. Reuse maintained task-to-public-metadata conversion without invoking a scope-wide task query or making it an authorization decision. Freeze that initial array once in the existing case-to-handoff reservation; replay returns it unchanged after current producer policy and exact handoff/source/binding/scope checks. A retry after a creation/association persistence gap MUST NOT replace missing initial facts with mutable `activeTasks` or a later task list. Existing TaskCreated provenance is useful identity evidence, but fields absent from it cannot be inferred as recorded facts.

`CaseFileRead.tasks` carries that same immutable initial creation array under the separately authorized current case-evidence read. Its initial references do not authorize a current task GET, list, action or socket delivery. Those operations continue to use their own current task-read/action decisions. Current task reassignment or completion does not rewrite the retained initial receipt.

`AcceptedIntakeEvidence` is also the protected source-service evidence response. It has no WOS identities, private storage keys, applicant secrets or transport credentials. WOS stores the initial qualified evidence with the durable case-to-handoff association. Missing prospective source evidence refuses; older records are never backfilled with invented session/history facts.

`GET /api/v1/cases/{case_id}/case-file` returns `CaseFileRead` only after independent reviewer authentication, matching storage scope and authorization to read this specific case evidence. It reads the immutable initial snapshot, never the latest Response or active authored version. Tasks use the maintained `TaskListItem` model and actual created runtime identities. The configured reviewer actor must map to the authenticated reviewer; a schema or actor slot does not prove that allocation.

`GET /api/v1/cases/{case_id}/case-file/attachments/{attachment_id}` selects the opaque attachment identifier from that case's immutable initial evidence. Authenticate and authorize again, select the stored source association, verify original length/MIME/hash using maintained source custody, and serve original bytes. Never fetch a caller URL, expose an object locator or forward an applicant token. The browser constructs this route from the case and opaque identifier; the descriptor contains no independent disclosure URL. MIME/hash verification makes no passport-photo compliance claim.

`GET /api/v1/cases/{case_id}/case-file/artifacts/{kind}?url={url}&version={version}&hash={hash}` returns original retained UTF-8 JSON bytes for one authored artifact already admitted in this case's initial evidence. `kind` is the existing authored artifact family (`definition`, `locale`, `component`, `theme`); all three query fields are required exact descriptor values. Reject malformed, missing, duplicate or unknown query fields. The URL is an identity selector, never a fetch destination. Missing or ambiguous exact descriptors refuse before source acquisition.

Resolve and authorize one immutable case-to-handoff reservation, and select the artifact from that same reservation. Check the actual caller, canonical actor, full deployment grant and exact workspace/environment, actual process/case association and workflow pins, source/Response/handoff, and unique admitted artifact descriptor. Recheck current caller authority after asynchronous metadata reads, before source acquisition, after source read and immediately before returning bytes; expired, revoked, changed or unavailable authority returns no bytes. Backend Evidence-purpose credentials reach only the configured source origin with redirects refused; the browser never supplies or receives them.

The source qualifies its retained evidence and exact artifact, and WOS checks original raw SHA-256 and parsed document equality against the admitted artifact before forwarding. Preserve original whitespace and key order: reserialized JSON does not satisfy the raw byte identity. This route uses the maintained bounded source read limit and rejects oversized content; it adds no public receipt or case-file DTO. A successful response uses `Content-Type: application/json; charset=utf-8`, `Cache-Control: private, no-store`, and `X-Content-Type-Options: nosniff`. Original raw artifact identity remains distinct from the semantic Definition hash. These bytes alone do not prove dynamic historical wording, recipient delivery or current authorization.

Errors use the existing problem response: `400` malformed path/query; `401` invalid or expired current bearer; `403` current caller/grant/resource refusal; `404` missing case/process/artifact; `409` ambiguous selection, corruption or source/handoff/document pin mismatch; `413` source body exceeds the maintained bound; `503` unavailable source or current authorization. Qualification requires exact original-byte equality, zero source acquisition for local refusal, and refusal after revocation during an asynchronous source read.

The source must validate the exact handoff, Response, ValidationReport, Definition, recorded Locale and material history against their canonical Formspec schemas. WOS-native code generation deliberately preserves these native JSON documents as `serde_json::Value` / TypeScript `unknown`, avoiding a partial cloned Formspec schema. JSON Schema validity alone does not qualify source evidence. Cross-field checks must establish handoff-to-Response/report/session/history association, full Response hash, exact Definition URL/version/canonical hash, and each raw authored artifact checksum. `definition.kind` must be `definition`; `displayedLocale.kind` must be `locale` and match the Response's exact URL/version/language. Omit displayedLocale only when genuine inline Definition wording was used. Additional artifacts contain only what this accepted render actually used.

Artifact `hash` commits to original retained raw UTF-8 bytes; `definitionHash` uses the maintained canonical semantic Definition hashing profile. Native parsed documents preserve exact values; source retains original bytes for checksum qualification. Full `responseHash` includes authored signatures and differs from `signedPayloadDigest`. Signature verification retains the actual source result and configured profile, with key/digest pins only when established. Neither acceptance nor pseudonymous session custody proves civil identity. Genuine material history may use ordinary custody without anchoring; an outbox or proof job identifier is not a history head.

The public OpenAPI snapshot declares the routes; the server owner registers implemented routes and emits the registry snapshot. Portal generation discovers `schemas/api`; Rust generation additionally requires the server owner to register `case-file` in its build resource list and generated module. Qualification requires maintained generation and owner-focused source/auth/custody/replay checks before activation. This specification authorizes no credentials, service activation or live filing.

The source evaluation blob is retained unchanged as `originalEvaluation`. It is not a canonical ValidationReport. The canonical `validationReport` must be produced once from that same actual result, original clock and pinned Definition through the maintained Formspec builder, then retained; reviewer reads perform no reevaluation. Signature `details` preserves the actual existing `verify_signed_response` receipt; status/profile describe that real verifier and configuration, with no synthetic receipt or unsupported key pin.

Owner-native fields explicitly set the maintained `json-schema-to-typescript` annotation `tsType: unknown`. This preserves the source-validation boundary in generated TypeScript; it does not assert object/scalar/array shape or change runtime JSON validation. The Rust generator retains `serde_json::Value`. Source canonical validators still establish the actual native document shape.

Attachment `fieldPath` is an RFC 6901 JSON Pointer rooted at the accepted `Response.data` value. D1 photo uses `/photo`; a repeated photo uses `/household/0/photo`. The source records the actual traversal pointer, preserves `~0`/`~1` escaping and verifies that resolving this pointer from `Response.data` yields the original accepted attachment descriptor. Consumers use that exact basis without stripping a `/data` prefix or converting a dotted item path. This WOS attachment association pointer is distinct from Formspec signature scope paths and metadata map keys.

Attachment `fileName` preserves the `filename` value at the recorded pointer in the exact accepted Response, frozen at acceptance. It identifies the name as filed. A display name may have changed before signing; this field does not claim an independently persisted upload-time filename. Do not invent a historical upload name from current metadata.
