# Initial accepted case file

`case-file.schema.json` (`https://schemas.formspec.io/wos-api/case-file/v1`) owns the WOS service evidence and reviewer read metadata. Formspec owns the native documents. The schema exports `AcceptedIntakeEvidence`, `CaseFileRead`, `IntakeHandoffReceipt`, `AcceptedAuthoredArtifact`, `AcceptedSignatureVerification`, and `AcceptedAttachmentDescriptor`.

`POST /api/v1/intake-handoffs` accepts the unchanged canonical Formspec IntakeHandoff1.0 from an authenticated, scope-bound integration principal. `Idempotency-Key` equals the original `handoffId`. The configured exact Definition binding selects the workflow; the caller supplies no workflow selector. Resolve and qualify source evidence before invoking maintained runtime acceptance. Return `accepted` only after a real case, process, and reviewer task commit. Replay returns those same identities. `pending` means retriable source qualification or delivery before runtime acceptance; it must not finalize a deferred runtime receipt. Altered content or binding under an existing scoped key refuses.

`AcceptedIntakeEvidence` is also the protected source-service evidence response. It has no WOS identities, private storage keys, applicant secrets or transport credentials. WOS stores the initial qualified evidence with the durable case-to-handoff association. Missing prospective source evidence refuses; older records are never backfilled with invented session/history facts.

`GET /api/v1/cases/{case_id}/case-file` returns `CaseFileRead` only after independent reviewer authentication, matching storage scope and authorization to read this specific case evidence. It reads the immutable initial snapshot, never the latest Response or active authored version. Tasks use the maintained `TaskListItem` model and actual created runtime identities. The configured reviewer actor must map to the authenticated reviewer; a schema or actor slot does not prove that allocation.

`GET /api/v1/cases/{case_id}/case-file/attachments/{attachment_id}` selects the opaque attachment identifier from that case's immutable initial evidence. Authenticate and authorize again, select the stored source association, verify original length/MIME/hash using maintained source custody, and serve original bytes. Never fetch a caller URL, expose an object locator or forward an applicant token. The browser constructs this route from the case and opaque identifier; the descriptor contains no independent disclosure URL. MIME/hash verification makes no passport-photo compliance claim.

The source must validate the exact handoff, Response, ValidationReport, Definition, recorded Locale and material history against their canonical Formspec schemas. WOS-native code generation deliberately preserves these native JSON documents as `serde_json::Value` / TypeScript `unknown`, avoiding a partial cloned Formspec schema. JSON Schema validity alone does not qualify source evidence. Cross-field checks must establish handoff-to-Response/report/session/history association, full Response hash, exact Definition URL/version/canonical hash, and each raw authored artifact checksum. `definition.kind` must be `definition`; `displayedLocale.kind` must be `locale` and match the Response's exact URL/version/language. Omit displayedLocale only when genuine inline Definition wording was used. Additional artifacts contain only what this accepted render actually used.

Artifact `hash` commits to original retained raw UTF-8 bytes; `definitionHash` uses the maintained canonical semantic Definition hashing profile. Native parsed documents preserve exact values; source retains original bytes for checksum qualification. Full `responseHash` includes authored signatures and differs from `signedPayloadDigest`. Signature verification retains the actual source result and configured profile, with key/digest pins only when established. Neither acceptance nor pseudonymous session custody proves civil identity. Genuine material history may use ordinary custody without anchoring; an outbox or proof job identifier is not a history head.

The public OpenAPI snapshot declares the routes; the server owner registers implemented routes and emits the registry snapshot. Portal generation discovers `schemas/api`; Rust generation additionally requires the server owner to register `case-file` in its build resource list and generated module. Qualification requires maintained generation and owner-focused source/auth/custody/replay checks before activation. This specification authorizes no credentials, service activation or live filing.

The source evaluation blob is retained unchanged as `originalEvaluation`. It is not a canonical ValidationReport. The canonical `validationReport` must be produced once from that same actual result, original clock and pinned Definition through the maintained Formspec builder, then retained; reviewer reads perform no reevaluation. Signature `details` preserves the actual existing `verify_signed_response` receipt; status/profile describe that real verifier and configuration, with no synthetic receipt or unsupported key pin.
