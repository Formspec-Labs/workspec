# Shared authoring replay vectors

`vectors.json` contains independently authored candidates, reviewed scenario expectations, and expected owner outcomes. MCP, synthesis/CLI, and Studio adoption must run this same corpus through their real entry points. The conformance integration test `common_literal_vectors_match_independent_expected_outcomes` is the owner reference.

For each vector, select `candidate` as the actual current project; pass `fixture` as fixture JSON. Resolve each dependency's `document` into immutable bytes with its declared role, URL, and version. Pass optional `requiredObservations`, `expectations`, and `clockStartMs` unchanged. `pass` requires all owner comparisons to pass; `fail` means native execution disagrees with the reviewed expectation; `refused` means preparation or a required observation cannot run. Do not rewrite expected values from observed output.

Execution uses in-memory WosRuntime and labeled fixture ports. Task authorization allows the assigned actor and grants no delegation. Formspec processing, service responses, and task presentation are fixtures; this corpus does not establish hosted authorization, real Formspec validation, external notice delivery, or durable execution. Native provenance identifiers remain real, independently minted identifiers; compare semantic outcomes, selected input identity, controlled time, process values, and traces rather than erasing those identifiers.

`posture-policy.json` separately checks a deployment-wide Posture Declaration bound by the selected workflow's native `signature.posturePolicy` URL and version. It has no workflow target. The positive case requires signature completion and the literal primitive-verification status; wrong and unresolved policy identities must refuse.

Notification controls establish native notice provenance and retain native template-not-found fallback warnings. They do not establish canonical `notifications.templates` rendering. A single delivery document cannot currently fill both calendar and notification roles because the replay selector refuses duplicate URL/version identities; provide separately identified dependencies. External delivery remains unsupported.

`unsupported-agent-shapes.json` preserves two historical schema/runtime discrepancy inputs unchanged. After fs-k07m they are retired malformed inputs: free-string capabilities, duplicate actor `type`, and incomplete kind-specific rules are refused by the canonical schema/native owner. Their old schema-valid label and old parser detail are historical. Refusal checks do not count as positive native rule coverage. Current executable native shape/policy controls live in `../native-ai-replay/vectors.json` and the independent native core/runtime tests; those establish policy stages only. Full invocation/preconditions remain fs-w9dv, governed output commitment fs-t9h8, and general operation evidence fs-pzju.
